## Verdict / 结论

The round-3 P0 is closed: a stored string can no longer be read back as an object. Worth recording, because the fix was not the obvious one — a marker guard was already in place when this round was reviewed, and it was not sufficient, since a string *beginning* with the marker was still treated as a payload. That remainder is now closed too, and the classes a payload may instantiate are bounded by a constructor argument. What remains is PSR-16 conformance work: expiry when `ttl <= 0`, unchecked return values, and key validation.

第三轮的 P0 已关闭：存入的字符串不可能再被读成对象。有一点值得记录，因为修法并非显而易见——本轮复核时代码里已有一层标记守卫，但它不充分：以标记**开头**的字符串仍会被当作载荷解析。该缺口现亦封堵，且载荷可实例化的类由构造参数限定。剩余为 PSR-16 一致性工作：`ttl <= 0` 时的过期语义、未检查的返回值、key 校验。

## P0

### P0-1

- **Status / 状态**: Fixed / 已修复
- **Where / 位置**: `src/RedisCache.php:64-71` (constructor), `220` (`withPrefix()`), `256-286` (`MARK`, `serialize()`, `unserialize()`)
- **Verification / 验证**: mechanism reproduced before and after the fix — the string `"\x00MG" . 'O:8:"stdClass":0:{}'` came back as a `stdClass` before and as the same string after; `"\x00MG" . serialize('hello')` came back as `hello` before and unchanged after. Regression tests added — `testMarkerPrefixedStringCarryingAnObjectPayloadStaysString`, `testMarkerPrefixedSerializedStringIsNotUnwrapped`, `testMarkerPrefixedStringSurvivesGetMultiple`, `testBinaryValueStartingWithMarkerRoundTrips`, `testAllowedClassesFalseBlocksInstantiation`, `testAllowedClassesFalseStillRoundTripsArrays`, `testWithPrefixKeepsAllowedClasses`
- **EN**: RedisCache writes strings raw and everything else serialised (`is_string($value) ? $value : serialize`), but on read it runs `@unserialize()` over **any** string without passing `allowed_classes`. A stored string like `'O:8:"stdClass":0:{}'` therefore comes back as an object rather than a string, and if that string came from user input it is an object-injection primitive. `getMultiple` and `getOrSet` share the path. **Fixed**: a marker guard had already landed before this pass, which closed the *plain* string case the finding describes. It did not close the case where a string begins with the marker: the marker was only checked, never escaped, so `"\x00MG" . 'O:8:"stdClass":0:{}'` still returned an object. `serialize()` now stores a marker-prefixed string as a payload too, which makes the marker decide unambiguously in both directions. `allowed_classes` is passed as well, defaulting to `true` so PSR-16 object support is unchanged, and settable to `false` or a class list for callers whose cache can be written from outside; `withPrefix()` carries the setting into the derived instance.
- **中文**: RedisCache 写入时字符串原样存、其余序列化（`is_string($value) ? $value : serialize`），读取时对**任意字符串**执行 `@unserialize()` 且未传 `allowed_classes`。后果：存入形如 `'O:8:"stdClass":0:{}'` 的字符串，读出来是对象而非字符串；若该字符串来自用户输入，即构成对象注入。`getMultiple` 与 `getOrSet` 同路径。**已修复**：本次修复之前已有一层标记守卫落地，它关掉了本条所述的**普通**字符串路径。但它没关掉「字符串以标记开头」这种情况：标记只被检查、从未被转义，故 `"\x00MG" . 'O:8:"stdClass":0:{}'` 仍会读成对象。`serialize()` 现将「以标记开头的字符串」也存为载荷，使标记在双向判断上都无歧义。同时开始传递 `allowed_classes`，默认 `true` 以保持 PSR-16 的对象支持不变，也可传 `false` 或类名列表，供缓存可能被应用外部写入的调用方使用；`withPrefix()` 会将该设置带入派生实例。
