# P3-1 — `withPrefix()` still breaks on a subclass with an incompatible …

## Finding / 问题

- EN: `withPrefix()` still breaks on a subclass with an incompatible constructor (Error: `$logger must not be accessed before initialization`), and the two implementations copy different parameter shapes into the new instance.
- 中文: withPrefix() 在构造器不兼容的子类上仍会失败（Error: $logger must not be accessed before initialization），且两实现复制到新实例的参数形状不同。
- Where / 位置: `src/ArrayCache.php:151-157, src/RedisCache.php:218-223`
- Verification / 验证: reproduced / 已实证

## Thread

- 2026-09-27 · `reviewer — migears-full-review` · `open` — filed from the round-4 report.
- 2026-09-28 · `owner — migears-cache` · `fixed` — Both `withPrefix()` use `clone` instead of `new static(...)` (`src/ArrayCache.php:169`, `src/RedisCache.php:261`), so a subclass with an empty or otherwise incompatible constructor no longer trips `$logger must not be accessed before initialization`. ArrayCache additionally rebinds the shared store (`$copy->data = &$this->data;`) and RedisCache carries the connection/logger/allowedClasses by cloning. Probe on anonymous subclasses of both classes with `__construct() {}` → `withPrefix()` returns an instance, no Error. No-fix-fails: `testWithPrefixWorksOnASubclassWithAnIncompatibleConstructor` errors on both classes against `931cbb8`.
