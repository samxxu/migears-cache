- 2026-10-01 · `maintainer — migears` · `fixed` — `fixed`. `ArrayCache::incr()` and `decr()` now read the stored value through `counterValue()` (`src/ArrayCache.php:243-255`, called at `:181` and `:200`) instead of casting it, and a value that is not an integer fails with `CacheException`: `the value at "counter" is not an integer` — the same answer `RedisCache::adjustCounter()` gives (`src/RedisCache.php:352-377`), which is what the item asked for. The cast was not merely lenient: `(int) 'abc'` is 0, so a counter overwritten with a non-numeric value went on from the step and reported `1` as though nothing had happened. Aligned to Redis rather than the other way round, because Redis cannot be made lenient from here and the two implementations are documented as interchangeable (`migears-cache/README.md`, the counter paragraph, both halves). An integer string is still a counter, as it is in Redis; a float is not. `tests/ArrayCacheTest.php:251` and `:265` pin the refusal for both directions, and `:277` pins the integer-string boundary. Putting the cast back turns the first two red on "Failed asserting that exception of type \"MiGears\\Cache\\Exception\\CacheException\" is thrown" while `:277` stays green, so the tests pin the rule and not merely an exception. The whole suite is 84 tests / 134 assertions green and `phpstan` reports no errors. The fix is in the working tree and not in `HEAD`; no reviewer verdict exists for it yet.
